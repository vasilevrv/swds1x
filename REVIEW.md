## Найдено и исправлено

1. Критическое: SDK 8258 `drv_gpio_irq_config()` задаёт callback, полярность
   и общую маску, но не включает маску самого пина. Добавлены отдельные
   `drv_gpio_irq_risc0_en()` / `drv_gpio_irq_risc1_en()`. До этого CF/CF1
   не принимались бы. Host-модель воспроизводит именно это поведение SDK.
2. При минимальном интервале отчётов 100 мс выборка с периодом 100 мс могла
   иногда оставлять окно пустым. Период передачи образцов в агрегацию сокращён
   до 50 мс. Это частота использования последних измерений, не частота
   физического обновления тока/напряжения.
3. Повторная инициализация теперь выключает IRQ пинов, сбрасывает состояние
   драйвера и старые измерения. IRQ включаются после установки исходной точки.
4. Исправлена конфигурация host-проверок HLW8032: определения типа измерителя
   доступны до условной компиляции драйвера.

## Оставшиеся аппаратные ограничения

- Начальные коэффициенты по R001 и делителю 1.991 MOhm / 998 Ohm требуют
  калибровки. Полный цикл V/I занимает около 6 секунд; по умолчанию отчёт 10 с.
- SDK блокирует IRQ при flash-записи/стирании: CF-импульсы за это время могут
  теряться. Непрерывный точный учёт энергии при таких паузах не подтверждён.
- NV сохраняется каждые 5 минут и дополнительно при отдельных событиях;
  резкое отключение питания может потерять последнюю несохранённую энергию.
- Фильтр сигнала перегрузки не отключает реле и не заменяет защиту платы.
- ADC PC5 оставлен по согласованию; его внутреннее подключение в ZT2S
  и поведение защиты flash при пониженном питании на плате не проверены.

# Ревью smart_plug — 2026-10-01

Область: все одиннадцать C-файлов приложения, конфигурация платы/стека, используемые
реализации UART, ZCL, таймеров и NV в локальном Telink SDK. Бинарные библиотеки

## Текущий вердикт перед прошивкой

### PC5: согласован первый стендовый запуск

Пользователь указал модуль Tuya ZT2S и разрешил оставить PC5 для проверки
на стенде. В распиновке Tuya PC5 не выведен; внутренняя схема отсутствует.
SDK допускает ADC на PB0..PB7, PC4/PC5. Из внешних контактов модуля возможны
PB7 (контакт RX №5) и PB1 (TX №7), если они не подключены на основной плате.
PC4 занят кнопкой, PB5 реле, PB4 подключён к зарезервированному RX HLW8032.
Для первого запуска PC5 оставлен; защита flash не отключалась. Проверить
показания ADC относительно питания МК и сохранение/восстановление NV.
Это согласование стендового эксперимента, не подтверждение production.
По [даташиту Tuya](https://developer.tuya.com/en/docs/iot/zt2s-module-datasheet?id=Kas9gdtath9p0)
номинальная flash ZT2S — 1024 KiB. Реальная TC32-сборка обоих образов
по-прежнему не выполнена в текущем окружении.

### Уточнение платы пользователем

Применена исправленная распиновка: PB5 — реле active high, PC4 — кнопка
active low с pull-up, PD2 — LED active low; HLW8032 TX → PC3 UART RX,
PF → PC2 input. HLW8032 RX подключён к PB4; этот вывод не является UART TX
8258, поэтому передача отключена (`UART_TX_NONE_PIN`), PB4 оставлен без
выходного драйвера/pull. RX HLW8032 зарезервирован и для чтения не требуется.
Board-файл общий для приложения и загрузчика; прежние выходы PA3/PA2 и
UART TX PC2 удалены из конфигурации.

Шунт R001 = 1 mOhm: номинальный коэффициент тока 1.000, milli = 1000.
IP/IN по 0.998 kOhm — фильтры. Цепочка к VP измерена как 1.991 MOhm;
VP–GND принят как 0.998 kOhm = 998 Ohm по контексту ответа пользователя.
Коэффициент напряжения `1991000 / (998 * 1000) ≈ 1.99499`: milli = 1995,
применён в board-файле; коэффициент тока milli = 1000. ADC PC5 по-прежнему
требует подтверждения свободного плавающего вывода. Калибровка по эталону
не выполнена; прежняя накопленная энергия автоматически не пересчитывается.
После изменения распиновки `make -C smart_plug check` — PASS: приложение
178 C-файлов, загрузчик 68 C-файлов, host-сценарии и BIN/merge. Проверка
использует SDK-заголовки и модельные GPIO/UART; уровни на плате не измерялись.
Лог: `/private/tmp/smart_plug_pin_update_checks.log`.
После уточнения VP–GND и применения коэффициента 1995 повторный
`make -C smart_plug check` — PASS. Проверены масштаб напряжения/мощности и
PF-энергии с новым коэффициентом; лог `/private/tmp/smart_plug_calibration_checks.log`.

### Дополнение: сборка загрузчика и объединённого BIN

Добавлены цели `bootloader` и `combined`, локальная board-конфигурация
загрузчика с отключённым UART update, объединение с проверкой CRC/слотов
и 16 KiB RAM code приложения. Проверены 68 C-файлов загрузчика с SDK.

проверка размера и ограничение очистки; граничные размеры проверены под

**НЕ ГОТОВО к production; текущую конфигурацию нельзя одобрить для прошивки

### Дополнительные исправления этого прохода

- **Критическое:** прежний лимит 448 KiB превышал реальный слот SDK 424 KiB.
  Исправлены Makefile и упаковщик; размер включает padding и CRC, увеличенный
  лимит отвергается. Проверены значения на границе слота.
- **Высокое:** парсеры SDK читали короткие ZCL payload без проверки длины.
  Добавлен входной guard для используемых foundation-команд, Groups/Scenes,
  On/Off, Identify и OTA. Vendor SDK не изменён. Входящие команды также
  блокируются во время factory reset.
- **Среднее:** backoff flash не охватывал принудительные записи при изменении
  настроек/выключении реле. Теперь эти пути тоже соблюдают повтор через 5 секунд.
- **Среднее:** валидные UART-кадры могли бесконечно поддерживать устаревшие RMS.
  Введён отдельный срок обновления каждой величины; ошибки диапазона проверяются
  в 64-битной арифметике до приведения к 32 битам. Энергия продолжает считаться.
- **Среднее:** изменение Power Parameter могло пересчитать приращение PF по
  неверному масштабу. При изменении параметра создаётся новая база PF.
- **Среднее:** переполнение диапазона Zigbee могло обрезать мощность/ток или
  завернуть UINT48 энергии. Используются invalid значения и насыщение накопленной
  энергии ниже зарезервированного UINT48 invalid; сохранённая сумма проверяется.
- **Среднее:** отказ Timed Off таймера мог оставить реле включённым навсегда.
  При отказе реле выключается; pairing/rejoin повторяют выделение таймеров через
  poll; таймер rejoin не начинает параллельный commissioning.
- Исправлены bitmap MeasurementType (active/apparent/phase A), добавлены Status
  и DemandFormatting Metering, boot-mode bit ImageType, привязка полярности кнопки к keyboard/pull, макросы указателей с
  правильными скобками; инициализация сбрасывает старые RAM-настройки/показания.
- Identify Stop очищает IdentifyTime; проверяются endpoint и reset pending.

- BIN header, padding, CRC и предел слота 424 KiB; атомарная замена BIN,
  обработка ошибки записи без частично опубликованного образа.
- Проверка с реальными флагами Makefile и `-Wall -Wextra`: предупреждений
  в коде приложения нет; остаются предупреждения SDK-заголовков и отличие
  поддерживаемых оптимизационных флагов Clang/TC32. Граф сборки уникален,
  содержит 178 C + 3 ASM, не включает lamp-приложение или host-тесты.

Эти проверки не запускают радио, DMA, flash или GPIO настоящего 8258 и не
заменяют компиляцию TC32. ASan fuzz проверяет входной guard, а не весь радио SDK.
Радиостек/драйверы в бинарных библиотеках недоступны для полного аудита.
Watchdog SDK сейчас отключён; его интервал и flash/OTA паузы требуют проверки
при стендовых испытаниях. Готовность массового изделия из этого ревью не следует.

## Повторное полное ревью

Проверены все исходники приложения, заголовки, board/stack/version config,
Makefile, упаковка BIN, тесты и используемые пути SDK: dispatch ZCL,
Configure Reporting, UART DMA/ошибки, NV и таймеры. Бинарные библиотеки SDK
доступны без исходников и не проходили полный аудит.

| Приоритет | Найдено при повторном ревью | Исправление |
|---|---|---|
| Высокий | Custom-кластер регистрировал NULL command handler; SDK вызывал его без проверки при cluster-specific команде | Зарегистрирован обработчик, возвращающий Unsupported Command |
| Высокий | Parity error UART не очищалась: общий HCI обработчик отключён в этой прошивке | Ошибочный DMA-пакет отбрасывается, флаг и FIFO очищаются, парсер пересинхронизируется |
| Высокий | Проверка PF использовала время разбора; накопленные кадры могли терять допустимую энергию из-за почти нулевого elapsed | Метки времени приёма в кольцевом буфере, восстановление времени байтов внутри DMA-пакета |
| Средний | Отказ выделения таймера после удержания кнопки оставлял reset pending навсегда | При отказе выполняется немедленный сброс |
| Средний | Во время ожидающего сброса poll продолжал накапливать энергию и мог заново записывать application NV | Poll прекращает обработку измерений и reporting до перезапуска |
| Средний | Standard reporting SDK мог обходить пользовательский интервал телеметрии | Для измерений оставлен единственный миллисекундный планировщик; Configure Reporting доступен для On/Off |
| Средний | Неполная сцена могла применить реле до обнаружения повреждённого остатка | Полная проверка TLV до изменения реле |
| Низкий | Отказ таймеров LED/Identify оставлял LED включённым или IdentifyTime без отсчёта | При отказе LED выключается, Identify завершается |
| Низкий | Изменение MAX_FIRMWARE_SIZE не влияло на уже собранный BIN | Ограничение размера добавлено в tracked settings Makefile |

Совместимость reporting: атрибуты измерений читаются стандартным Read Attributes
и отправляются стандартным Report Attributes. Configure Reporting для этих
атрибутов возвращает ошибку SDK о неподдерживаемой отчётности; координатору
нужна настройка через `0xFC00/0x0000`. Это осознанный выбор для соблюдения
заданного пользователем единого интервала, включая 100 мс. Автоматическую
настройку конкретной интеграции координатора ещё нужно проверить.

Повторная проверка: `make -C smart_plug check` — PASS. Добавлены сценарии
UART parity с/без DMA IRQ, задержанный разбор нескольких кадров, два кадра
в одном DMA-пакете, короткая кнопка, порог 10 секунд, отсутствие toggle после
долгого нажатия, отказ таймеров reset/LED, повреждённые сцены, ненулевой
command handler custom-кластера. ASan/UBSan прошли; все 177 C-файлов проходят
синтаксическую проверку с заголовками SDK; проверки упаковки BIN/CRC прошли.

`make -C smart_plug check-tools` подтверждает отсутствие `tc32-elf-gcc`.
Полная компиляция/линковка TC32 и испытания на плате остаются непроверенными.
Метки времени UART добавляют 512 байт статической RAM; её итоговый запас

## Оставшиеся ограничения

1. Быстрый аппаратный сброс PF около границы переполнения может быть
   неотличим от небольшого обычного прироста. Защита ограничивает ложный скачок,
   но гарантированное обнаружение требует дополнительного аппаратного сигнала.
2. Первый абсолютный PF после запуска и энергия за разрыв UART более двух
   секунд не восстанавливаются. Сумма из flash сохраняется; сомнительная разность
   к ней не добавляется. Остаток менее 1 µWh хранится только в RAM.
3. При пропадании питания теряется энергия после последней успешной записи
   flash, обычно до пяти минут; при неисправной flash потеря может быть больше.
4. GPIO, полярности и коэффициенты калибровки пока предварительные. После
   прозвонки меняются также соответствующие `PAx/PDx` GPIO-настройки в board-файле.
5. Телеметрия отправляется координатору endpoint 1. Требуются проверки на
   выбранном координаторе, включая чтение/запись custom-кластера и нагрузку
   сети при 100 мс. На этом интервале отправляются два отчёта за окно.
6. TC32-компилятор не найден в PATH. Полная линковка, размеры flash/RAM,
   UART DMA/IRQ на 8258, физическая кнопка/LED/реле, pairing и OTA требуют
   сборки SDK-проекта и проверки платы. Добавлен отдельный Makefile для TC32,
   включая startup, linker script и обработку BIN/CRC. Синтаксическая проверка
   полного набора из 177 C-файлов проходит в bootloader-режиме. SDK запрещает
   normal mode для выбранного B85(1M), Makefile это ограничение проверяет. При этой
   проверке выявлена и добавлена обязательная для SDK настройка ADC защиты
   flash: временный плавающий PC5, даже при отключённом VOLTAGE_DETECT_ENABLE.
