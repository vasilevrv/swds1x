# Финальное ревью swrelay2x — 2026-10-04

Проверены текущие исходники приложения и загрузчика, реальный Telink SDK, Makefile, упаковщики BIN/OTA, внешний конвертер, тесты и документация. Ревью охватывает изменения относительно проекта розетки и взаимодействие нового кода с SDK. TC32-компиляция/линковка и работа на плате не выполнялись по договорённости с пользователем.

## Найденные и исправленные ошибки

После проверки собранного пользователем OTA обнаружена **P1 — неверное смещение версии в упаковщике**. `make_ota.py` читал четыре байта с `0x04`, тогда как TLSR8258 помещает FILE_VERSION после двухбайтовой TJ по адресу `0x02`. Build 4 получал OTA version `0x00001104`, ниже установленного build 2, и обновление не выбиралось. Смещение исправлено. Тест теперь использует реальную компоновку заголовка SDK и воспроизводит ошибочное значение при чтении с `0x04`; дополнительно проверяется, что OTA version выше установленного build 2. Ранее тестовая заготовка ошибочно размещала версию по тому же смещению, что и упаковщик, поэтому не выявляла дефект. TC32-сборка остаётся этапом пользователя.

В версии `0x11034001` снижено число записей APP NV: изменения состояния канала сохраняются только для `previous`/`toggle`. Для `off`/`on` общая запись содержит фиксированное стартовое значение; переключения другого канала или сохранение настройки не делают его состояние причиной записи. При смене политики на `previous`/`toggle` сохраняется текущее состояние. Проверены 200 переключений двух каналов в фиксированных режимах без дополнительных записей, восстановление без записи при старте, независимые режимы и переходы между политиками. Формат NV остаётся совместимым.

Дополнительно после проверки на устройстве исправлена **P2 — локальная ошибка `UNSUPPORTED_CLUSTER relay2Config` после загрузки конвертера**: описание пользовательского кластера теперь регистрируется перед чтением/записью настроек, даже если start/configure ещё не выполнялись. Регрессионный тест с настоящим herdsman воспроизводит отказ разрешения имени кластера в пустом реестре и проверяет успешные set/get без предварительной конфигурации. Тесты конвертера прошли; изменения прошивки для исправления не нужны.

1. **P2 — зависание OffWaitTime после бессрочного включения.** Команда On With Timed Off с `OnTime=0xFFFF` и конечным `OffWaitTime` не требовала таймера во включённом состоянии. Последующее обычное OFF меняло состояние, но не запускало отсчёт ожидания. Следующие команды On With Timed Off могли постоянно попадать в ветку ожидания. Теперь обновление состояния запускает необходимый таймер соответствующего канала. Исправление: `relay2_onOffUpdate()` / `relay2_onOffTimerSync()` в [zcl_on_off.c](zcl_on_off.c).

2. **P2 — отсутствие отсчёта после записи атрибутов.** `OnTime` и `OffWaitTime` доступны для записи, однако обработчик foundation-команд реагировал только на StartUpOnOff. Конечное значение счётчика могло остаться без таймера. Теперь обработчик записи синхронизирует таймер. Исправление: [zcl_callbacks.c](zcl_callbacks.c). Проверено по реальному `zcl.c` SDK: приложение получает callback после попытки записи атрибутов.

Добавлены регрессионные сценарии в [tests/test_relay.c](tests/test_relay.c). Отказ выделения таймера выключает реле и очищает счётчики; очистка выполняется до повторного обновления состояния, чтобы избежать рекурсивных попыток выделения.

## Оставшиеся замечания

1. **P2 — событие может потеряться при отказе постановки в отправку.** В [relay_2ch.c](relay_2ch.c), `relay2_buttonEvent()`, результат `zcl_sendCmd()` не обрабатывается. Реальный SDK возвращает `ZCL_STA_INSUFFICIENT_SPACE`, если не выделен буфер либо `af_dataSend()` отклонил отправку. APS ACK помогает уже принятой стеком передаче; при отказе постановки повторной попытки в приложении нет. Локальное переключение связанного реле при этом уже выполнено. Это особенно заметно в логическом режиме кнопки. Радиодоставка после успешной постановки также не подтверждается приложением. Текущая доставка событий — с подтверждением APS, без гарантии получения каждого действия автоматизацией.

2. **P3 — On With Recall Global Scene реализован как обычный ON.** В [zcl_on_off.c](zcl_on_off.c) команда `0x41` возвращает успех, но не сохраняет/восстанавливает отдельную global scene. Обычные Store Scene / Recall Scene обрабатываются отдельно и проверены. Это ограничение дополнительной команды On/Off; обычное управление двумя реле и кнопочные режимы от него не зависят.

Критических ошибок P0/P1 в проверенных программных сценариях не обнаружено. Это заключение не заменяет проверку прошивки на устройстве.

## Выполненные проверки

```sh
RELAY_ZHC_DIR=/tmp/relay-2ch-node-check make check
git diff --check
```

Все проверки прошли. C-тесты собраны Clang с AddressSanitizer и UndefinedBehaviorSanitizer. Выполнена проверка синтаксиса полного набора **179 C-файлов приложения/SDK и 69 C-файлов загрузчика/SDK** с производственной распиновкой и настоящими заголовками SDK. Интеграционный тест конвертера использует `zigbee-herdsman-converters@26.108.1`. Успешный путь загрузчика проверен с имитацией flash; алгоритм CRC отдельно проверен тестами упаковщиков.

Проверка синтаксиса Clang не подтверждает TC32 ABI, ассемблер, линковку, итоговый размер RAM/flash или выполнение на MCU.

## Аппаратная приёмка

После самостоятельной сборки и прошивки проверить:

1. Оба реле и LED неактивны при старте загрузчика; включение каждого endpoint меняет только своё реле.
2. Для каждой кнопки все четыре сочетания linked/double, одиночное и двойное нажатие, hold, одновременное нажатие двух кнопок; в логическом режиме реле не меняется.
3. Сохранение настроек/состояний после отключения питания, все четыре режима StartUpOnOff отдельно по каналам.
4. Локальные single при выключенном координаторе; восстановление связи, поступление новых событий и отсутствие накопленных событий из периода без сети.
5. Служебный reset 10 секунд, повторное подключение, настройки по умолчанию, Identify на обоих endpoint.
6. Последующее OTA, перезапуск и сохранение настроек. Подтвердить TLSR8258 / flash 1 MiB и отсутствие внешнего подключения PC5, который SDK использует для контроля питания.

Команды сборки и аппаратной записи: [BUILD_AND_FLASH.md](BUILD_AND_FLASH.md). Формат и передача OTA: [OTA_UPDATE.md](OTA_UPDATE.md).
