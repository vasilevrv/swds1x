# Обновление SWPLUG1x по Zigbee OTA

На плате уже должны быть установлены загрузчик и приложение этого проекта
для TLSR8258 с flash 1 MiB. Первый переход со штатной Tuya-прошивки выполняется
проводным программатором по [инструкции](BUILD_AND_FLASH.md).

## 1. Собрать OTA-файл

Из корня проекта:

```sh
make -C smart_plug -j4 ota TOOLCHAIN_PREFIX=/path/to/bin/tc32-elf-
```

Если toolchain находится в PATH, аргумент `TOOLCHAIN_PREFIX` можно убрать.
Результат: **`smart_plug/build/boot1/smart_plug.zigbee`**.
Эта цель собирает приложение и упаковывает его для OTA. Загрузчик в OTA
не входит. Для загрузки через Zigbee используйте именно `.zigbee`.

Упаковщик `tools/make_ota.py` проверяет соответствие `.raw.bin` и `.bin`, CRC,
размер образа, резерв RAM загрузчика и идентификаторы приложения. Версию
берёт из `.raw.bin`: подготовка `.bin` заменяет часть поля версии маркером CRC.
Полезная нагрузка сохраняется вместе с Telink CRC внутри стандартного
Zigbee OTA-контейнера, без шифрования.

Текущая сборка 04: manufacturer code `0x1141`, image type `0x03D2`,
file version `0x10044001`, Basic SW build `2026100104`.
Числовой manufacturer code сохранён для совместимости с предыдущими сборками.
Если на розетке уже стоит эта версия, повторная OTA-загрузка будет отклонена:
для следующих изменений увеличьте `APP_BUILD` в `version_cfg.h` и обновите
Basic SW build в `zcl_clusters.c` перед сборкой.

## 2. Обновить конвертер Zigbee2MQTT

Замените установленный внешний конвертер содержимым
[`smart_plug_hlw8032.mjs`](zigbee2mqtt/smart_plug_hlw8032.mjs) из проекта.
В нём включено `ota: true`; имя файла сохранено для существующих установок.
Перезапустите Z2M. Инструкция установки: [zigbee2mqtt/README.md](zigbee2mqtt/README.md).

## 3. Загрузить образ

В актуальном Z2M откройте раздел OTA, выберите розетку и загрузите
`smart_plug.zigbee` через диалог собственного файла прошивки.
Точное название кнопки зависит от версии интерфейса.

Если диалога нет, скопируйте файл на сервер Z2M, например в каталог данных
`ota/swplug1x.zigbee`, и отправьте MQTT-запрос:

Топик (замените `zigbee2mqtt`, если у вас другой `base_topic`):

```text
zigbee2mqtt/bridge/request/device/ota_update/update
```

Сообщение:

```json
{"id":"0xa4c138dfd7d62904","url":"/app/data/ota/swplug1x.zigbee"}
```

`id` может быть IEEE-адресом или friendly name. Путь в `url` должен быть доступен
**процессу Z2M**. Для Docker это путь внутри контейнера; `/app/data/ota/` —
пример, проверьте свою точку монтирования. Путь к файлу на Mac не подойдёт,
если Z2M запущен на другом компьютере. HTTP(S)-ссылка на файл также допустима.
Для такого прямого запроса отдельный OTA-индекс не нужен. Обычная кнопка проверки
обновлений без собственного файла не найдёт нашу прошивку в публичном каталоге.

Прямая загрузка файла и загрузка из интерфейса описаны в
[официальной документации Z2M](https://www.zigbee2mqtt.io/guide/usage/ota_updates.html).

## 4. Дождаться завершения

Следите за прогрессом в Z2M. Оставьте розетку включённой до завершения;
обновление может занять десятки минут. После получения и проверки образа
устройство перезапускается, а Z2M выполняет interview/configure.
После перезапуска состояние реле определяется настройкой `power_on_behavior`.

Заводской сброс для обновления не требуется. Интервал телеметрии и сохранённая
энергия остаются в NV; сохранение последнего несохранённого приращения энергии
при OTA-перезапуске на плате ещё не подтверждено.
Проверьте Basic SW build `2026100104` и новые показания напряжения/тока
после нескольких окон измерения. Коэффициенты активной мощности и энергии
по CF пока требуют отдельной калибровки.

## Статус проверки

Добавлены цель сборки, упаковщик и поддержка в конвертере. TC32-сборка и
полный цикл OTA с реальной платой в этой среде не выполнены: toolchain отсутствует.
После калибровочных изменений сборок 03/04 и добавления OTA-упаковщика тесты
не запускались. Успешные прежние проверки относятся к сборке 02.
